# Звіт до лабораторної роботи №10

## Тема роботи

Узагальнені контейнери та ітератори в Java.

## Варіант

Варіант 5 — ігровий інвентар.

## Мета роботи

Метою лабораторної роботи є отримання практичних навичок реалізації власного узагальненого контейнера та власного ітератора в Java.

Також метою роботи є навчитися відокремлювати внутрішню структуру зберігання даних від механізму обходу елементів та забезпечити підтримку циклу `for-each` через інтерфейс `Iterable<T>`.

---

## 1. Опис предметної області

У лабораторній роботі розглядається предметна область ігрового інвентаря.

У такій моделі є гравець, ігрові предмети та слоти спорядження. Гравець може мати інвентар, у якому зберігаються різні предмети: зброя, броня, кільця, зілля та інші об'єкти.

Для зберігання предметів було реалізовано власний узагальнений контейнер `InventoryContainer<T>`. Він може працювати не тільки з предметами типу `Item`, а й з іншими типами даних, наприклад `String`.

---

## 2. Класи предметної області

### 2.1 Клас `Player`

Клас `Player` описує гравця.

Поля класу:

- `nickname` — нікнейм гравця;
- `level` — рівень гравця.

Клас містить конструктор, гетери та метод `toString()`.

У конструкторі передбачено перевірки:

- нікнейм не може бути порожнім;
- рівень гравця має бути додатним числом.

---

### 2.2 Клас `Item`

Клас `Item` описує ігровий предмет.

Поля класу:

- `name` — назва предмета;
- `slot` — слот спорядження;
- `power` — сила предмета.

Клас містить конструктор, гетери та метод `toString()`.

У конструкторі передбачено перевірки:

- назва предмета не може бути порожньою;
- слот предмета не може бути `null`;
- сила предмета не може бути від'ємною.

---

### 2.3 Перелік `EquipmentSlot`

`EquipmentSlot` реалізовано як `enum`.

Він описує допустимі слоти спорядження:

- `WEAPON`;
- `ARMOR`;
- `HELMET`;
- `RING`;
- `POTION`.

Використання `enum` є зручним, тому що слот предмета не зберігається довільним рядком. Це зменшує кількість можливих помилок у програмі.

---

## 3. Реалізований контейнер

У роботі реалізовано власний generic-контейнер:

```java
InventoryContainer<T>
```

Контейнер є узагальненим, тому може зберігати об'єкти різних типів.

Наприклад:

```java
InventoryContainer<Item> inventory = new InventoryContainer<>();
InventoryContainer<String> notes = new InventoryContainer<>();
```

Це показує, що один і той самий клас контейнера можна повторно використовувати з різними типами без дублювання коду.

Контейнер не є обгорткою над `ArrayList` або іншою стандартною колекцією Java. Він реалізований самостійно на основі внутрішнього масиву.

---

## 4. Внутрішнє подання контейнера

Внутрішнє сховище контейнера реалізовано через масив:

```java
private Object[] items;
```

Для зберігання кількості реально доданих елементів використовується поле:

```java
private int size;
```

Масив `items` відповідає за фізичне зберігання елементів, а `size` показує, скільки елементів зараз знаходиться в контейнері.

Таке рішення дозволяє самостійно реалізувати логіку додавання, видалення, доступу за індексом та обходу елементів.

---

## 5. Основні методи контейнера

### 5.1 Метод `add(T item)`

Метод додає новий елемент у кінець контейнера.

Перед додаванням перевіряється, чи не дорівнює елемент `null`.

Якщо місця у внутрішньому масиві вже немає, викликається метод `grow()`, який збільшує місткість масиву.

---

### 5.2 Метод `get(int index)`

Метод повертає елемент за індексом.

Перед отриманням елемента виконується перевірка індексу. Якщо індекс неправильний, генерується `IndexOutOfBoundsException`.

Неправильним вважається індекс, який менший за `0` або більший чи рівний `size`.

---

### 5.3 Метод `remove(int index)`

Метод видаляє елемент за індексом і повертає видалений елемент.

Після видалення всі наступні елементи зсуваються вліво. Остання зайва позиція масиву очищується, а значення `size` зменшується на одиницю.

Це потрібно, щоб у контейнері не залишалося пропусків між елементами.

---

### 5.4 Метод `size()`

Метод повертає поточну кількість елементів у контейнері.

---

### 5.5 Метод `capacity()`

Метод повертає поточну місткість внутрішнього масиву.

Цей метод зручний для демонстрації автоматичного розширення контейнера.

---

### 5.6 Метод `isEmpty()`

Метод перевіряє, чи є контейнер порожнім.

Якщо `size` дорівнює `0`, метод повертає `true`.

---

### 5.7 Метод `clear()`

Метод очищує контейнер.

Він проходить по всіх доданих елементах, зануляє їх у масиві та встановлює `size` у значення `0`.

---

## 6. Автоматичне розширення масиву

У контейнері реалізовано автоматичне розширення внутрішнього масиву.

Якщо під час додавання нового елемента масив уже заповнений, викликається приватний метод:

```java
grow()
```

У цьому методі створюється новий масив, який у 2 рази більший за попередній. Після цього всі старі елементи копіюються у новий масив.

Це дозволяє додавати більше елементів, ніж було передбачено початковою місткістю контейнера.

---

## 7. Реалізація власного ітератора

Власний ітератор реалізовано як внутрішній клас:

```java
private class InventoryIterator implements Iterator<T>
```

Ітератор має поле:

```java
private int currentIndex;
```

Це поле зберігає індекс поточного елемента під час обходу контейнера.

Ітератор реалізує два основні методи:

```java
hasNext()
```

Метод перевіряє, чи є ще елементи для обходу.

```java
next()
```

Метод повертає наступний елемент контейнера.

Якщо елементів більше немає, метод `next()` генерує виняток `NoSuchElementException`.

---

## 8. Підтримка `Iterable<T>` і циклу `for-each`

Клас `InventoryContainer<T>` реалізує інтерфейс:

```java
Iterable<T>
```

Для цього в контейнері перевизначено метод:

```java
@Override
public Iterator<T> iterator()
```

Цей метод повертає новий об'єкт власного ітератора.

Завдяки цьому контейнер можна використовувати у циклі `for-each`:

```java
for (Item item : inventory) {
    System.out.println(item);
}
```

Тобто клієнтський код може обходити елементи контейнера, не знаючи, як саме вони зберігаються всередині.

## 9. Демонстрація роботи програми

У класі `Main` демонструється робота ігрового інвентаря.

Послідовність дій у програмі:

1. Створюється об'єкт `Player`.
2. Створюються кілька об'єктів `Item`.
3. Створюється контейнер `InventoryContainer<Item>`.
4. Предмети додаються в контейнер.
5. Виводиться кількість предметів.
6. Виводиться місткість контейнера.
7. Демонструється отримання предмета за індексом.
8. Демонструється обхід через звичайний `Iterator`.
9. Демонструється обхід через цикл `for-each`.
10. Видаляється предмет за індексом.
11. Повторно виводиться інвентар після видалення.
12. Додатково демонструється робота generic-контейнера з типом `String`.

Приклад фрагмента виводу:

```text
=== Ігровий інвентар ===
Гравець: Artem, рівень: 15

Додавання предметів:
Кількість предметів: 4
Місткість контейнера: 6

Отримання предмета за індексом:
Предмет: Сталевий меч, слот: WEAPON, сила: 25
```

## 12. Додаткове завдання

У роботі додатково реалізовано автоматичне розширення внутрішнього масиву.

Якщо кількість елементів досягає поточної місткості, контейнер створює новий масив більшого розміру та копіює в нього старі елементи.

Також реалізовано метод:

```java
clear()
```

Він дозволяє повністю очистити контейнер.

Ці можливості роблять контейнер зручнішим для практичного використання.

У ході виконання лабораторної роботи було реалізовано модель ігрового інвентаря для варіанта 5.

Було створено класи предметної області:

- `Player`;
- `Item`;
- `EquipmentSlot`.

Для зберігання елементів було реалізовано власний generic-контейнер:

```java
InventoryContainer<T>
```

Контейнер використовує внутрішній масив `Object[]`, підтримує додавання, доступ за індексом, видалення, визначення розміру, перевірку на порожнечу, очищення та автоматичне розширення.

Також було реалізовано власний ітератор `InventoryIterator`, який дозволяє послідовно обходити елементи контейнера.

Завдяки реалізації `Iterable<T>` контейнер можна використовувати у циклі `for-each`.

Отже, лабораторна робота показала, як працюють самописні generic-контейнери, власні ітератори та механізм підтримки `for-each` у Java.
