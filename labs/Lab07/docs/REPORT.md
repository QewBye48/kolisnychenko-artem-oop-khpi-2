# Звіт до лабораторної роботи №7

## Тема роботи

Інтерфейси та множинна реалізація інтерфейсів у Java.

## Варіант

Варіант 5 — засоби командної роботи над проєктами.

## Мета роботи

Метою лабораторної роботи є отримання практичних навичок використання інтерфейсів у Java.

У роботі потрібно показати, як інтерфейси можуть описувати поведінкові контракти, як конкретні класи реалізують ці контракти, а також як один клас може реалізовувати більше ніж один інтерфейс.

---

## 1. Опис предметної області

У даній лабораторній роботі розглядається предметна область засобів командної роботи над проєктами.

У таких системах можуть існувати різні об'єкти:

- картка завдання;
- звіт про помилку;
- примітка до рев'ю.

Деякі з цих об'єктів можна призначати виконавцю. Деякі можна коментувати. Також є об'єкти, які підтримують обидві можливості одночасно.

Тому для цієї моделі доцільно використати інтерфейси, які описують саме поведінку об'єктів.

---

## 2. Використані інтерфейси

У роботі створено два інтерфейси:

```text
Assignable
Commentable
```

### `Assignable`

Інтерфейс `Assignable` описує об'єкти, які можна призначити виконавцю.

Методи інтерфейсу:

```java
String assignTo(String personName);

String getAssignee();
```

Цей інтерфейс є змістовним, тому що у системі командної роботи часто є об'єкти, які мають відповідального виконавця.

### `Commentable`

Інтерфейс `Commentable` описує об'єкти, до яких можна додавати коментарі.

Методи інтерфейсу:

```java
String addComment(String comment);

int getCommentsCount();
```

Цей інтерфейс є змістовним, тому що в командній роботі важливо залишати коментарі до завдань, помилок або приміток.

---

## 3. Реалізовані класи

У роботі реалізовано три конкретні класи:

```text
TaskCard
BugReport
ReviewNote
```

### `TaskCard`

Клас `TaskCard` описує картку завдання.

Поля класу:

- `title` — назва завдання;
- `description` — опис завдання;
- `assignee` — виконавець;
- `commentsCount` — кількість коментарів.

Клас реалізує два інтерфейси:

```java
public class TaskCard implements Assignable, Commentable
```

Це логічно, тому що завдання можна призначити виконавцю і до нього можна додавати коментарі.

### `BugReport`

Клас `BugReport` описує звіт про помилку.

Поля класу:

- `bugId` — номер помилки;
- `severity` — рівень важливості;
- `assignee` — виконавець;
- `commentsCount` — кількість коментарів.

Клас також реалізує два інтерфейси:

```java
public class BugReport implements Assignable, Commentable
```

Це є коректним, тому що помилку можна призначити відповідальному виконавцю і до неї можна додавати коментарі.

### `ReviewNote`

Клас `ReviewNote` описує примітку до рев'ю.

Поля класу:

- `author` — автор примітки;
- `text` — текст примітки;
- `commentsCount` — кількість коментарів.

Клас реалізує тільки інтерфейс:

```java
public class ReviewNote implements Commentable
```

Це логічно, тому що примітку можна коментувати, але її не обов'язково призначати виконавцю.

---

## 4. Множинна реалізація інтерфейсів

У роботі є класи, які реалізують більше ніж один інтерфейс.

Клас `TaskCard` реалізує:

```text
Assignable
Commentable
```

Клас `BugReport` також реалізує:

```text
Assignable
Commentable
```

Це демонструє множинну реалізацію інтерфейсів у Java.

Така модель є змістовною, тому що завдання і звіт про помилку мають дві незалежні можливості:

- їх можна призначати виконавцю;
- до них можна додавати коментарі.

---

## 5. Використання інтерфейсів у клієнтському коді

Інтерфейсно-орієнтований клієнтський код показано у класі `Main`.

Спочатку створюються об'єкти:

```java
TaskCard task = new TaskCard("Створити сторінку входу", "Додати просту форму авторизації");
BugReport bug = new BugReport("BUG-101", "Висока");
ReviewNote note = new ReviewNote("Артем", "Код потребує невеликих виправлень");
```

Далі об'єкти обробляються через інтерфейс `Assignable`:

```java
Assignable[] assignableItems = {
        task,
        bug
};

for (Assignable item : assignableItems) {
    System.out.println(item.assignTo("Колісниченко Артем"));
}
```

У цьому фрагменті програма не працює напряму з `TaskCard` або `BugReport`. Вона працює з ними через тип інтерфейсу `Assignable`.

Також об'єкти обробляються через інтерфейс `Commentable`:

```java
Commentable[] commentableItems = {
        task,
        bug,
        note
};

for (Commentable item : commentableItems) {
    System.out.println(item.addComment("Перевірено куратором проєкту"));
}
```

Тут різні класи обробляються однаково, бо всі вони реалізують інтерфейс `Commentable`.

---

## 6. Один об'єкт через два різні інтерфейси

У роботі також показано один об'єкт через два різні інтерфейсні подання.

Приклад з класу `Main`:

```java
Assignable assignableView = task;
Commentable commentableView = task;

System.out.println(assignableView.assignTo("Іван Петренко"));
System.out.println(commentableView.addComment("Завдання було перепризначено"));
```

Об'єкт `task` має тип `TaskCard`, але його можна використовувати як `Assignable` і як `Commentable`.

Це показує, що один клас може підтримувати кілька незалежних ролей.

---

## 7. Чому інтерфейси краще, ніж тільки успадкування

У цій роботі інтерфейси є кращим рішенням, ніж побудова однієї ієрархії класів.

Причина в тому, що `Assignable` і `Commentable` описують не тип об'єкта, а його можливість.

Наприклад:

- `TaskCard` можна призначати і коментувати;
- `BugReport` можна призначати і коментувати;
- `ReviewNote` можна тільки коментувати.

Ці класи не обов'язково мають бути частиною однієї жорсткої ієрархії успадкування. Але вони можуть мати спільні поведінкові контракти.

Саме тому інтерфейси краще виражають цю модель.

## 11. Додаткове завдання: аналіз попередньої моделі

У попередніх лабораторних роботах розглядалася модель спортивного клубу.

У ній були такі класи:

```text
SportsClub
Student
Coach
SportSection
Schedule
Enrollment
```

У цій моделі можна використати інтерфейси для опису окремих можливостей.

Наприклад, можна виділити інтерфейс:

```text
Printable
```

або:

```text
Describable
```

Його могли б реалізовувати класи:

- `Student`;
- `Coach`;
- `SportSection`;
- `Enrollment`.

Також можна було б виділити інтерфейс:

```text
Schedulable
```

Його міг би реалізовувати клас `SportSection`, тому що секція має розклад.

Таке перепроєктування може покращити модель, тому що дозволяє працювати з об'єктами за їхніми можливостями, а не створювати штучне успадкування між несхожими класами.

## 12. Висновок

У ході виконання лабораторної роботи було створено модель засобів командної роботи над проєктами.

Було реалізовано два інтерфейси:

- `Assignable`;
- `Commentable`.

Також було створено три конкретні класи:

- `TaskCard`;
- `BugReport`;
- `ReviewNote`.

Класи `TaskCard` і `BugReport` реалізують два інтерфейси, що демонструє множинну реалізацію інтерфейсів у Java.

У класі `Main` було показано інтерфейсно-орієнтований клієнтський код: об'єкти обробляються через типи `Assignable` і `Commentable`.

Таке рішення є зручним, тому що інтерфейси описують незалежні поведінкові ролі об'єктів і не змушують будувати штучну ієрархію класів.
