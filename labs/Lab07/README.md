# Лабораторна робота №7

## Тема

Інтерфейси та множинна реалізація інтерфейсів у Java.

## Варіант

Варіант 5 — засоби командної роботи над проєктами.

## Мета роботи

Мета роботи — навчитися використовувати інтерфейси в Java як поведінкові контракти.

У роботі потрібно показати:

- створення інтерфейсів;
- реалізацію інтерфейсів у конкретних класах;
- множинну реалізацію інтерфейсів;
- використання `@Override`;
- роботу клієнтського коду через типи інтерфейсів.

---

## Ідея програми

Програма моделює прості об'єкти, які можуть використовуватися в командній роботі над проєктами.

У системі є:

- картка завдання;
- звіт про помилку;
- примітка до рев'ю.

Деякі об'єкти можна призначати виконавцю, деякі можна коментувати, а деякі підтримують обидві можливості.

---

## Інтерфейси

### `Assignable`

Інтерфейс описує об'єкти, які можна призначити виконавцю.

Методи:

```java
String assignTo(String personName);

String getAssignee();
```

### `Commentable`

Інтерфейс описує об'єкти, до яких можна додавати коментарі.

Методи:

```java
String addComment(String comment);

int getCommentsCount();
```

---

## Класи

### `TaskCard`

Клас описує картку завдання.

Реалізує:

- `Assignable`;
- `Commentable`.

Це означає, що завдання можна призначити виконавцю і до нього можна додавати коментарі.

---

### `BugReport`

Клас описує звіт про помилку.

Реалізує:

- `Assignable`;
- `Commentable`.

Це означає, що помилку можна призначити відповідальному виконавцю і до неї можна додавати коментарі.

---

### `ReviewNote`

Клас описує примітку до рев'ю.

Реалізує:

- `Commentable`.

Це означає, що до примітки можна додавати коментарі, але її не потрібно призначати виконавцю.

---

## Множинна реалізація інтерфейсів

У роботі є класи, які реалізують більше ніж один інтерфейс.

Наприклад:

```java
public class TaskCard implements Assignable, Commentable{}
```

та:

```java
public class BugReport implements Assignable, Commentable{}
```

Це є змістовним, тому що і завдання, і звіт про помилку можуть одночасно мати виконавця та коментарі.

---

## Інтерфейсно-орієнтований клієнтський код

У класі `Main` програма працює не тільки з конкретними класами, а й через типи інтерфейсів.

Приклад обробки через `Assignable`:

```java
Assignable[] assignableItems = {
    task,
    bug
};
```

Приклад обробки через `Commentable`:

```java
Commentable[] commentableItems = {
    task,
    bug,
    note
};
```

Також один об'єкт використовується через два різні інтерфейсні подання:

```java
Assignable assignableView = task;
Commentable commentableView = task;
```

## Висновок

У лабораторній роботі було створено просту модель засобів командної роботи над проєктами.

Інтерфейси `Assignable` і `Commentable` описують окремі поведінкові ролі. Класи `TaskCard` і `BugReport` реалізують обидва інтерфейси, тому можуть бути одночасно призначені виконавцю і прокоментовані. Клас `ReviewNote` реалізує тільки `Commentable`, бо примітку до рев'ю потрібно коментувати, але не обов'язково призначати виконавцю.

У класі `Main` показано обробку об'єктів через типи інтерфейсів. Це демонструє інтерфейсно-орієнтоване проєктування та множинну реалізацію інтерфейсів у Java.
