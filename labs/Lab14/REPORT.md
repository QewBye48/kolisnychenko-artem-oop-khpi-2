# Звіт до лабораторної роботи №14

## Тема

Базова багатопотоковість у Java.

## Варіант

5 — медіатека.

## Мета роботи

Набути практичних навичок базового багатопотокового програмування в Java: створення потоків, запуску паралельних дій, використання `sleep()` та `join()`, а також аналізу недетермінованого порядку виконання потоків.

## Реалізована модель

У роботі створено класи `Movie`, `Podcast`, `MediaCatalog`, сервіс `MediaService`, клас потоку `CatalogScanThread` та завдання `SortTask` і `RecommendationTask`.

## Багатопотоковий сценарій

У `Main` запускаються три робочі потоки:

- `CatalogScanThread` — сканування медіакаталогу;
- `SortThread` — сортування фільмів за рейтингом;
- `RecommendationThread` — генерація рекомендацій для користувача.

Клас `CatalogScanThread` реалізований через наслідування від `Thread`.

Класи `SortTask` і `RecommendationTask` реалізовані через інтерфейс `Runnable`.

Усі потоки запускаються через метод `start()`. Після запуску головний потік `main` очікує їх завершення через `join()`, тому фінальні результати виводяться тільки після завершення всієї роботи.

## Що демонструється

У роботі показано:

- створення потоку через `extends Thread`;
- створення завдання через `implements Runnable`;
- запуск потоків через `start()`;
- використання `Thread.sleep()` для імітації поетапної роботи;
- використання `Thread.currentThread().getName()` для виведення імен потоків;
- очікування завершення потоків через `join()`;
- недетермінований порядок виконання потоків;
- тестування детермінованої логіки без залежності від планувальника потоків.

## Тестування

У роботі реалізовано модульні тести для перевірки логіки, яка не залежить від випадкового порядку виконання потоків.

Тести перевіряють:

- сортування фільмів за рейтингом;
- обчислення середнього рейтингу;
- формування списку рекомендованих фільмів;
- роботу `RecommendationTask` при прямому виклику `run()`.

Точний порядок виконання потоків у тестах не перевіряється, тому що він залежить від планувальника потоків і може змінюватися при кожному запуску.

## Висновок

У роботі продемонстровано базові засоби багатопотоковості Java без складної синхронізації спільного стану.

Показано обидва способи створення потоку: через наслідування від `Thread` і через реалізацію `Runnable`.

У програмі запускаються три незалежні робочі потоки: сканування каталогу, сортування фільмів і генерація рекомендацій. Для запуску використано `start()`, для імітації тривалої роботи — `Thread.sleep()`, а для очікування завершення всіх потоків — `join()`.

Окремо протестовано детерміновану логіку сервісу та завдань без прив’язки до випадкового порядку виконання потоків.
