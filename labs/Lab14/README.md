# Lab 14 — Базова багатопотоковість у Java

## Варіант

Варіант 5 — медіатека.

## Тема роботи

Базова багатопотоковість у Java.

## Суть задачі

Потрібно реалізувати консольну Java-програму, яка демонструє базову роботу з потоками.

У програмі має бути предметна область, кілька незалежних завдань, запуск потоків через `start()`, імітація тривалої роботи через `Thread.sleep()` та очікування завершення потоків через `join()`.

У цій роботі предметна область — медіатека.

---

## Предметна область

У проєкті реалізовано медіатеку, яка містить фільми та подкасти.

Основні класи предметної області:

- `Movie` — фільм з назвою, жанром, рейтингом і тривалістю;
- `Podcast` — подкаст з назвою, ведучим і кількістю епізодів;
- `MediaCatalog` — каталог медіатеки, який зберігає списки фільмів і подкастів.

---

## Сервісний клас

Для обробки даних використовується клас:

- `MediaService`

Він містить логіку, яка не залежить від потоків і може бути протестована окремо.

Клас `MediaService` виконує такі дії:

- сканує каталог;
- сортує фільми за рейтингом;
- формує список рекомендованих фільмів;
- обчислює середній рейтинг фільмів.

---

## Багатопотоковий сценарій

У проєкті показано базову роботу з потоками.

Реалізовано три незалежні завдання:

- сканування медіакаталогу;
- сортування фільмів за рейтингом;
- генерація рекомендацій.

Для цього створено такі класи:

- `CatalogScanThread` — потік через `extends Thread`;
- `SortTask` — завдання через `implements Runnable`;
- `RecommendationTask` — завдання через `implements Runnable`.

---

## Потік через `extends Thread`

Клас `CatalogScanThread` наслідує клас `Thread`.

Він відповідає за сканування медіакаталогу.

У методі `run()` потік:

- виводить повідомлення про початок роботи;
- імітує поетапне сканування через `Thread.sleep()`;
- викликає метод сервісу `scanCatalog()`;
- зберігає результат сканування;
- виводить повідомлення про завершення роботи.

---

## Завдання через `implements Runnable`

У роботі також використано два класи, які реалізують інтерфейс `Runnable`.

### `SortTask`

Клас `SortTask` відповідає за сортування фільмів за рейтингом.

Завдання запускається в окремому потоці:

```java
Thread sortThread = new Thread(sortTask, "SortThread");
```

### `RecommendationTask`

Клас `RecommendationTask` відповідає за формування списку рекомендованих фільмів.

Завдання запускається в окремому потоці:

```java
Thread recommendationThread = new Thread(recommendationTask, "RecommendationThread");
```

---

## Демонстраційна програма

У класі `Main` створюються тестові дані:

- список фільмів;
- список подкастів;
- об'єкт `MediaCatalog`;
- об'єкт `MediaService`.

Після цього створюються три робочі потоки:

```java
CatalogScanThread scanThread = new CatalogScanThread(catalog, service);

SortTask sortTask = new SortTask(catalog, service);
Thread sortThread = new Thread(sortTask, "SortThread");

RecommendationTask recommendationTask = new RecommendationTask(catalog, service);
Thread recommendationThread = new Thread(recommendationTask, "RecommendationThread");
```

---

## Запуск потоків

Усі потоки запускаються методом `start()`:

```java
scanThread.start();
sortThread.start();
recommendationThread.start();
```

Метод `start()` створює новий потік виконання.

Прямий виклик `run()` не створює нового потоку, тому для демонстрації багатопотоковості використовується саме `start()`.

---

## Очікування завершення потоків

Після запуску потоків головний потік `main` очікує завершення всіх робочих потоків через `join()`:

```java
scanThread.join();
sortThread.join();
recommendationThread.join();
```

Це потрібно для того, щоб результати потоків виводилися тільки після завершення їхньої роботи.

---

## Імена потоків

У програмі використовуються власні імена потоків:

- `CatalogScanThread`;
- `SortThread`;
- `RecommendationThread`.

У методах `run()` використовується:

```java
Thread.currentThread().getName()
```

Це дозволяє бачити в консолі, який саме потік виконує певну дію.

---

## Імітація тривалої роботи

Для імітації поетапної або тривалої роботи використано:

```java
Thread.sleep()
```

Це дозволяє показати, що потоки виконуються незалежно один від одного, а порядок їхніх повідомлень у консолі може змінюватися.

---

## Що демонструється

У лабораторній роботі демонструється:

- створення потоку через `extends Thread`;
- створення завдання через `implements Runnable`;
- запуск потоків через `start()`;
- використання `Thread.sleep()` для імітації тривалої роботи;
- використання `Thread.currentThread().getName()`;
- власні імена потоків;
- очікування завершення потоків через `join()`;
- недетермінований порядок виконання потоків;
- тестування детермінованої логіки окремо від планувальника потоків.

## Перевірка багатопотоковості

Для перевірки багатопотоковості можна поставити breakpoint після запуску потоків:

```java
scanThread.start();
sortThread.start();
recommendationThread.start();
```

Після цього в Debug можна перевірити стани потоків через `getState()`:

```java
"scan=" + scanThread.getState()
        + ", sort=" + sortThread.getState()
        + ", recommendation=" + recommendationThread.getState()
```

Приклад результату:

```text
scan=RUNNABLE, sort=RUNNABLE, recommendation=RUNNABLE
```

Це означає, що всі три потоки були запущені та передані JVM для виконання.

Також можливий стан `TIMED_WAITING`, якщо потік у цей момент перебуває в `Thread.sleep()`. Це також є нормальним результатом, бо потік уже запущений.

Тестові класи:

## Висновок

У лабораторній роботі реалізовано просту медіатеку з використанням базової багатопотоковості Java.

Було створено класи предметної області `Movie`, `Podcast` і `MediaCatalog`, а також сервіс `MediaService`.

У програмі показано два способи створення потоків: через наслідування від `Thread` і через реалізацію `Runnable`.

Потоки запускаються через `start()`, імітують поетапну роботу через `Thread.sleep()`, виводять власні імена в консоль і завершуються з очікуванням через `join()`.

Детермінована логіка винесена в `MediaService`, тому її можна перевіряти модульними тестами без залежності від випадкового порядку виконання потоків.
