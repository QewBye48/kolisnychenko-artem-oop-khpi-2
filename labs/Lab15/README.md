# Lab 15

Синхронізація потоків у Java.

Варіант 5 — лічильник подій.

## Предметна область

У роботі реалізовано спільний лічильник подій.

Кілька потоків одночасно збільшують один спільний лічильник. Без синхронізації частина оновлень може втрачатися, тому фактичний результат може бути меншим за очікуваний.

## Суть задачі

Потрібно показати проблему спільного доступу до змінюваних даних у багатопотоковій програмі.

У роботі реалізовано два варіанти лічильника:

* небезпечний варіант без синхронізації;
* коректний варіант із використанням `synchronized`.

Після запуску програма порівнює очікуваний і фактичний результат для обох сценаріїв.

## Що реалізовано

У проєкті реалізовано такі класи:

* `SharedCounter` — інтерфейс спільного лічильника;
* `UnsafeSharedCounter` — небезпечний лічильник без синхронізації;
* `SafeSharedCounter` — синхронізований лічильник;
* `EventSource` — джерело подій;
* `CounterResult` — результат виконання сценарію;
* `CounterTask` — задача для потоку;
* `CounterService` — сервіс для запуску сценаріїв і формування звіту;
* `Main` — демонстраційна програма.

## Спільний ресурс

Спільним ресурсом є лічильник подій.

У класах лічильника є поле:

```java
private int value;
```

Це поле змінюється кількома потоками одночасно.

## Небезпечний варіант

Клас `UnsafeSharedCounter` реалізує збільшення лічильника без синхронізації.

Метод `increment()` виконує операцію збільшення неатомарно:

```java
int current = value;
value = current + 1;
```

Операція складається з кількох кроків:

1. прочитати поточне значення;
2. обчислити нове значення;
3. записати результат.

Якщо кілька потоків виконують ці кроки одночасно, один потік може перезаписати результат іншого. Через це частина оновлень втрачається.

## Синхронізований варіант

Клас `SafeSharedCounter` використовує `synchronized`.

У ньому синхронізовані методи:

```java
public synchronized void increment()
public synchronized int getValue()
public synchronized void reset()
```

Завдяки цьому тільки один потік одночасно може змінювати стан лічильника.

Це захищає критичну секцію і гарантує правильний фінальний результат.

## Багатопотоковий сценарій

У програмі запускаються 4 потоки.

Кожен потік виконує 100000 збільшень спільного лічильника.

Очікуваний результат:

```text
4 * 100000 = 400000
```

У небезпечному варіанті без `synchronized` фактичний результат може бути меншим за 400000.

У синхронізованому варіанті результат має дорівнювати 400000.

## Параметри запуску

* кількість потоків: 4;
* кількість операцій на потік: 100000;
* загальна кількість операцій: 400000;
* початкове значення лічильника: 0;
* очікуваний результат: 400000.

## Висновок

У лабораторній роботі реалізовано спільний лічильник подій для демонстрації синхронізації потоків у Java.

Було показано, що без синхронізації кілька потоків можуть одночасно змінювати одне поле `value`, через що виникає стан перегонів і частина оновлень може втрачатися.

У синхронізованому варіанті метод `increment()` захищений ключовим словом `synchronized`, тому одночасно його може виконувати тільки один потік.

Після використання `synchronized` фінальний результат збігається з очікуваним значенням.

Отже, синхронізація дозволяє захистити критичну секцію і забезпечити коректну роботу програми зі спільним змінюваним ресурсом.
