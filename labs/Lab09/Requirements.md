# Вимоги до програми
## Лабораторна робота №9
## Варіант 5 — Медичні записи

## Загальні вимоги

1. Програма повинна бути написана мовою Java.
2. Програма повинна реалізовувати просту модель медичних записів.
3. У програмі потрібно використати узагальнення Generics.
4. Generic-компонент має бути пов'язаний із предметною областю, а не бути формальним прикладом.
5. Програма повинна працювати у консольному режимі.
6. Проєкт повинен бути Maven-проєктом.

---

## Функціональні вимоги

1. Програма повинна містити предметні класи:
    - `Patient`;
    - `Visit`;
    - `Prescription`.

2. Програма повинна дозволяти створювати пацієнта.

3. Програма повинна дозволяти створювати медичний візит пацієнта.

4. Програма повинна дозволяти створювати рецепт для пацієнта.

5. Програма повинна містити generic-клас для типобезпечного збереження медичного запису разом із метаданими.

6. Generic-клас повинен мати два параметри типу:

```java
MedicalRecord<TEntity, TMeta>
```

7. У програмі потрібно показати щонайменше дві конкретизації generic-класу:

```java
MedicalRecord<Visit, String>
MedicalRecord<Prescription, Integer>
```

8. Програма повинна містити generic-метод для аналізу медичних даних.

9. Generic-метод повинен мати обмеження параметра типу:

```java
<T extends Comparable<? super T>>
```

10. Generic-метод повинен знаходити максимальний елемент у списку.

11. Для класу `Visit` порівняння повинно виконуватися за датою візиту.

12. Для класу `Prescription` порівняння повинно виконуватися за тривалістю лікування в днях.

---

## Вимоги до класів

### `Patient`

Клас описує пацієнта.

Поля:

- `patientId` — ідентифікатор пацієнта;
- `fullName` — ПІБ пацієнта;
- `age` — вік пацієнта.

Клас повинен містити:

- конструктор;
- гетери;
- метод `toString()`.

---

### `Visit`

Клас описує візит пацієнта до лікаря.

Поля:

- `visitId` — ідентифікатор візиту;
- `patient` — пацієнт;
- `visitDate` — дата візиту;
- `doctorName` — ім'я лікаря.

Клас повинен реалізовувати:

```java
Comparable<Visit>
```

Порівняння виконується за датою візиту.

---

### `Prescription`

Клас описує рецепт.

Поля:

- `prescriptionId` — ідентифікатор рецепта;
- `patient` — пацієнт;
- `medicineName` — назва препарату;
- `doseMg` — доза препарату в міліграмах;
- `days` — тривалість лікування в днях.

Клас повинен реалізовувати:

```java
Comparable<Prescription>
```

Порівняння виконується за кількістю днів лікування.

---

### `MedicalRecord<TEntity, TMeta>`

Generic-клас для зберігання медичного запису разом із метаданими.

Поля:

- `entity` — основний об'єкт запису;
- `metadata` — додаткова інформація про запис.

Клас повинен містити:

- конструктор;
- `getEntity()`;
- `getMetadata()`;
- `toString()`.

---

### `MedicalUtils`

Утилітарний клас для generic-методу.

Повинен містити метод:

```java
public static <T extends Comparable<? super T>> T findMaximum(List<T> items)
```

Метод повинен:

- приймати список об'єктів;
- повертати максимальний елемент;
- повертати `null`, якщо список порожній або дорівнює `null`;
- працювати тільки з типами, які можна порівнювати.

---

## Вимоги до демонстрації в `Main`

У класі `Main` потрібно показати:

1. Створення об'єкта `Patient`.
2. Створення двох об'єктів `Visit`.
3. Створення двох об'єктів `Prescription`.
4. Використання generic-класу:

```java
MedicalRecord<Visit, String>
```

5. Використання generic-класу:

```java
MedicalRecord<Prescription, Integer>
```

6. Використання generic-методу `findMaximum()` для пошуку найпізнішого візиту.

7. Використання generic-методу `findMaximum()` для пошуку рецепта з найбільшою тривалістю лікування.

---

## Вимоги до тестування

1. Тести повинні бути написані з використанням JUnit Jupiter.
2. Тести повинні перевіряти клас `Patient`.
3. Тести повинні перевіряти клас `Visit`.
4. Тести повинні перевіряти клас `Prescription`.
5. Тести повинні перевіряти generic-клас `MedicalRecord`.
6. Тести повинні перевіряти generic-метод `MedicalUtils.findMaximum()`.
7. Тести повинні перевіряти роботу generic-класу у двох конкретизаціях:
    - `MedicalRecord<Visit, String>`;
    - `MedicalRecord<Prescription, Integer>`.
8. Тести повинні перевіряти роботу generic-методу з різними типами:
    - `Visit`;
    - `Prescription`;
    - `Integer`.

## Нефункціональні вимоги

1. Код повинен бути простим і зрозумілим.
2. Назви класів, методів і змінних повинні відповідати їхньому призначенню.
3. Не можна використовувати сирі типи.
4. Не повинно бути небезпечних приведень типів.
5. Generic-компонент повинен реально покращувати типобезпеку програми.
6. Проєкт повинен містити UML-діаграму.
7. Проєкт повинен містити `README.md`.
8. Проєкт повинен містити `REPORT.md`.
9. Проєкт повинен містити `pom.xml`.
