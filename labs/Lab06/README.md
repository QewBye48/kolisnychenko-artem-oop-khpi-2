# Лабораторна робота №6

## Тема

Поліморфізм з абстрактними класами в Java.

## Варіант

Варіант 5 — способи доставки.

## Мета роботи

Мета роботи — навчитися створювати поліморфні моделі у Java з використанням абстрактних класів.

У роботі потрібно показати:

- абстрактний базовий клас;
- спільний стан у базовому класі;
- абстрактний метод;
- конкретні підкласи;
- перевизначення методів через `@Override`;
- поліморфний виклик через базовий тип.

## Ієрархія класів

У роботі реалізовано таку ієрархію:

```text
DeliveryMethod
├── CourierDelivery
├── ParcelLockerDelivery
└── DroneDelivery
```

## Опис класів

### `DeliveryMethod`

Абстрактний базовий клас, який описує загальний спосіб доставки.

Спільні поля:

- `orderId` — номер замовлення;
- `address` — адреса доставки;
- `basePrice` — базова вартість доставки.

Методи:

- `getOrderId()`;
- `getAddress()`;
- `getBasePrice()`;
- `getInfo()`;
- `calculatePrice()` — абстрактний метод для розрахунку вартості доставки.

### `CourierDelivery`

Клас кур'єрської доставки.

Додає власне поле:

- `distanceKm` — відстань доставки в кілометрах.

Метод `calculatePrice()` рахує вартість доставки з урахуванням відстані.

### `ParcelLockerDelivery`

Клас доставки до поштомата.

Додає власне поле:

- `lockerNumber` — номер поштомата.

Метод `calculatePrice()` додає фіксовану доплату до базової ціни.

### `DroneDelivery`

Клас доставки дроном.

Додає власне поле:

- `weightKg` — вага посилки.

Метод `calculatePrice()` рахує вартість доставки з урахуванням ваги.

## Поліморфізм

Поліморфізм показано в класі `Main`.

Об'єкти різних підкласів зберігаються в масиві базового типу:

```java
DeliveryMethod[] deliveries = {
    new CourierDelivery(...),
    new ParcelLockerDelivery(...),
    new DroneDelivery(...)
};
```

Після цього для кожного об'єкта викликається метод:

```java
delivery.calculatePrice();
```

Хоча змінна має тип `DeliveryMethod`, Java виконує метод того класу, об'єкт якого реально знаходиться в масиві.

## Що реалізовано

У лабораторній роботі реалізовано:

- абстрактний клас `DeliveryMethod`;
- три конкретні підкласи:
    - `CourierDelivery`;
    - `ParcelLockerDelivery`;
    - `DroneDelivery`;
- спільний стан у базовому класі;
- абстрактний метод `calculatePrice()`;
- перевизначення методу `calculatePrice()` у кожному підкласі;
- перевизначення методу `getInfo()`;
- поліморфний виклик через масив `DeliveryMethod[]`;
- UML-діаграму;
- TestNG-тести.

## Висновок

У роботі було створено просту поліморфну модель способів доставки.

Абстрактний клас `DeliveryMethod` містить спільні поля та спільну поведінку для всіх типів доставки. Конкретні класи `CourierDelivery`, `ParcelLockerDelivery` і `DroneDelivery` реалізують власний розрахунок вартості доставки.

Поліморфізм проявляється в тому, що всі об'єкти обробляються через базовий тип `DeliveryMethod`, але метод `calculatePrice()` виконується по-різному залежно від фактичного типу об'єкта.
